## 2. 副本集 rs0（任务三 / 任务五）
三个节点，keyFile 内部认证 + 账号授权：

```bat
mongod --port 27017 --dbpath .\rs1 --bind_ip 127.0.0.1 --replSet rs0 --keyFile .\deploy\keyfile.txt --auth --logpath .\logs\rs1.log
mongod --port 27018 --dbpath .\rs2 --bind_ip 127.0.0.1 --replSet rs0 --keyFile .\deploy\keyfile.txt --auth --logpath .\logs\rs2.log
mongod --port 27019 --dbpath .\rs3 --bind_ip 127.0.0.1 --replSet rs0 --keyFile .\deploy\keyfile.txt --auth --logpath .\logs\rs3.log
```

初始化（任一节点执行一次）：

```javascript
rs.initiate({
  _id: "rs0",
  members: [
    { _id: 0, host: "127.0.0.1:27017", priority: 2 },
    { _id: 1, host: "127.0.0.1:27018", priority: 1 },
    { _id: 2, host: "127.0.0.1:27019", priority: 1 }
  ]
})
```

账号（localhost 例外窗口内创建，创建后即强制认证）：

| 账号 | 认证库 | 角色 | 密码 |
|---|---|---|---|
| libAdmin | admin | userAdminAnyDatabase, clusterAdmin | <自行设置> |
| libReader | library | read | <自行设置> |
| libWriter | library | readWrite | <自行设置> |

## 3. 分片集群（任务六）
端口规划：config 副本集 27200、分片 sh1 27201、sh2 27202、mongos 27217；数据目录 `shard_test\{config,shard1,shard2}`。

```bat
mongod --port 27200 --dbpath .\shard_test\config --configsvr --replSet cfgRS --bind_ip 127.0.0.1 --auth --keyFile .\deploy\keyfile.txt
mongod --port 27201 --dbpath .\shard_test\shard1 --shardsvr --replSet sh1 --bind_ip 127.0.0.1 --auth --keyFile .\deploy\keyfile.txt
mongod --port 27202 --dbpath .\shard_test\shard2 --shardsvr --replSet sh2 --bind_ip 127.0.0.1 --auth --keyFile .\deploy\keyfile.txt
mongos --port 27217 --configdb cfgRS/127.0.0.1:27200 --keyFile .\deploy\keyfile.txt
```

顺序很关键：三个 mongod 起来 → 三个副本集各自 rs.initiate() 并选出 PRIMARY → 再启 mongos（提前启 mongos 会因找不到 config 主节点直接退出）。

mongos 上创建管理账号 shardAdmin / <自行设置>（userAdminAnyDatabase + clusterAdmin），再：

```javascript
sh.addShard("sh1/127.0.0.1:27201")
sh.addShard("sh2/127.0.0.1:27202")
sh.enableSharding("library")
sh.shardCollection("library.borrow_logs", { reader_card: "hashed" })
```

应用账号 libApp / <自行设置>（library 库 readWrite、dbAdmin），供程序与检索使用。

## 4. 程序运行
`config.json` 保存连接串（打印时已脱敏）；也可用环境变量覆盖：

```bat
set MONGODB_URI=mongodb://libWriter:<自行设置>@127.0.0.1:27017,27018,27019/library?replicaSet=rs0&authSource=library
set MONGODB_SHARD_URI=mongodb://libApp:<自行设置>@127.0.0.1:27217/library?authSource=library
python 01_main.py
```

config.json 的字段：`uri`（主程序）、`db`、`admin_uri`（运维脚本）、`standalone_uri`（初始化）、
`shard_uri`（菜单 17 走 mongos）、`shard_admin_uri`（`verify_topology.py` 查分片清单）、`repl_members`（成员列表）、`repl_set`（集合名，默认 rs0）。

**工作目录无关**：代码里所有文件路径都以 `os.path.dirname(os.path.abspath(__file__))` 为基准，
所以在任意目录下用完整路径运行都可以（实测：把源码拷到 `D:\tmp\teacher_test`，在 `C:\` 下执行
`python D:\tmp\teacher_test\01_main.py`，菜单 0/1/2/16/12 全部正常，导出与下载文件都落在源码目录）。

### 4.1 副本集初始化与故障转移脚本
```bat
REM 三个 mongod 都已用同一 --replSet / 同一 keyFile 启动后，初始化一次即可
python init_repl.py
REM 故障转移：先运行，脚本写基线并提示你结束主节点进程，之后自动计时到新主接管
python test_failover.py
```
- `init_repl.py` 的成员取自 `repl_members` 或 `MONGODB_REPL_MEMBERS`，集合名取自节点启动参数里的 `--replSet`
  （再退到 `repl_set` / `MONGODB_REPL_SET`），第 1 个成员 priority=2；对已初始化的集群重复执行只打印角色、不报错。
- `test_failover.py` 实测：停掉主节点后约 9.7 秒新主接管、期间失败重试 2 次，重启原主 2.1 秒内以 SECONDARY 回归。

- 导入：程序菜单 **0**（或 `data_initializer.py`）；核对：菜单 1 / 证据图 A-3。

## 6. 复现要点
1. 先起副本集，再起分片集群（互不冲突：27017–27019 与 27200–27217）。
2. 分片数据的分布验证一律通过 mongos 的 `collStats` / `explain`，不要直连分片节点用业务账号认证（会报 code 18）。
3. 故障转移演练：`taskkill /F /PID <主节点 pid>` → 观察新主选出；重启原主后按 priority=2 会重新当选。

结论先说：**不需要装 mongosh，也不需要看代码**，三种方式任选，结论应当一致。

### 7.1 方式一：一条命令看端口（30 秒）


| | 27019 | mongod 3 | SECONDARY |
| 分片集群（任务六） | 27200 | mongod（config） | 配置服务器副本集 cfgRS |
| | 27201 | mongod（shardsvr） | 分片 sh1 |
| | 27202 | mongod（shardsvr） | 分片 sh2 |
| | 27217 | mongos | 路由进程（客户端唯一入口） |

### 7.3 方式三：MongoDB Compass 图形化

1. 副本集：新建连接，Hosts 填三个种子地址（不是只填 27017）
   `127.0.0.1:27017,127.0.0.1:27018,127.0.0.1:27019`，
   Authentication 选 Username/Password，用 **libReader / <自行设置>**，Authentication Database 填 `library`，
   Replica Set Name 填 `rs0` → Connect。
   **验证点**：窗口标题栏与左上角面包屑会显示这三个地址，说明客户端是通过副本集拓扑连上的；
   左侧 Databases 里能看到 `library` 的 7 个集合。
2. 分片：再建一条连接，Host 填 `127.0.0.1:27217`，用 **shardAdmin / <自行设置>**，Authentication Database 填 `admin`。
   进去点右上角 **⋮ → Open MongoDB shell**，执行：

```javascript
sh.status()                                   // 看分片列表与已分片集合
db.getSiblingDB("admin").runCommand({listShards: 1})
```

   期望：两个分片 `sh1` / `sh2`，`library.borrow_logs` 的 chunks 分布在两片。
3. 也可以用 Compass 的 Explain Plan：对 `library.borrow_logs` 按 `{reader_card: "R20240001"}` 查询，
   Explain 里出现 **SINGLE_SHARD**（只打一片）；换成 `{status: "已归还"}` 则是 **SHARD_MERGE**（广播两片）。

### 7.5 三个容易踩的坑（老师自查时可能遇到）

1. **直连分片节点（27201/27202）用业务账号认证会失败**（报 `Authentication failed` code 18）
   —— 分片节点之间只认 keyFile 内部认证，业务访问一律走 mongos 27217。
2. **`libApp` 没有 `listShards` 权限**（`not authorized on admin`），查分片清单要用 `shardAdmin`；
   同理 `libAdmin` 只有 admin 库权限，**读不了 library 业务数据**（要读用 `libReader` / `libWriter`）。
3. **启动顺序**：三个 mongod → 三个副本集各自选出 PRIMARY → 才启 mongos；先启 mongos 会因找不到 config 主节点退出。
   `netstat` 里 27217 不在，通常就是这个原因。
